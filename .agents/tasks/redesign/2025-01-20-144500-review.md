# Frontend redesign: blue/white theme and product image upload

UI redesign of SaleBySale user and admin frontends replacing dark theme with clean blue/white color scheme and adding supplier product image upload with preview. Login demo chips removed, landing pages differentiated, button text updated from "Enter network" to "Sign In", and backend extended with image storage fields. The redesign preserves all existing functionality while improving visual consistency and adding the requested image upload capability.

**Watch for:** Admin inventory table missing image column (confirmed). Admin register page includes Rider role and /register route is exposed despite no UI link. No build verification performed — both frontends need `npm run build` to confirm no compile errors.

**Verdict**: NEEDS_CHANGES

## High-level view

The color scheme migration is complete across both frontends: CSS variables changed from dark/gold/teal to blue (#2563eb primary, #1e40af primary-dark, #dbeafe primary-light) with white backgrounds and gray neutrals. Login pages cleaned up: demo user suggestion chips ("Admin", "Supplier · Shiv Ganga", "Buyer retailer", "Rider") removed from both, button text changed to "Sign In". Landing pages now properly differentiated: user frontend targets "Retailers & Wholesalers" with register options for both roles, admin landing shows "Admin Portal" with single sign-in button and no register link (though /register route still exists). 

Supplier image upload implemented: file input accepts up to 5 images (2MB each, jpeg/png/webp), converts to base64, shows grid preview with primary image selection and delete buttons, sends images array and primaryImage to backend. Backend Inventory model extended with images (array) and primaryImage (string) fields, availability endpoint returns both. Buyer search displays primaryImage in offer cards (200px wide, 150px tall, rounded corners). Admin inventory table shows supplier names but no image column. User registration page cleaned (only Retailer/Wholesaler), admin registration still has Rider. Admin creation script exists at scripts/createAdminSimple.js with clear instructions.

## Supplier image upload: file input to base64 storage

Supplier.jsx (SupplierStock component) image upload implementation:

**Frontend** (salebysale-users-frontend/src/pages/Supplier.jsx):
- File input: `<input type="file" accept="image/jpeg,image/png,image/webp" multiple onChange={handleImageUpload} />`
- handleImageUpload: slices first 5 files, checks each < 2MB, converts to base64 via FileReader, appends to images state array
- Preview grid: displays images in 120px-wide cards, border highlights primary image (3px solid primary vs 1px line)
- Primary selection: button on each preview toggles primaryImageIndex state
- Delete button: filters out image from array, adjusts primaryImageIndex if needed
- Form submission: sends `{ ...form, images, primaryImage: images[primaryImageIndex] || null }` to POST /supplier/inventory

**Backend** (salebysale-backend):
- Inventory model (models/Inventory.js): added `images: { type: [String], default: [] }` and `primaryImage: { type: String, default: null }`
- Supplier route (routes/supplier.js): POST /supplier/inventory extracts images and primaryImage from req.body, saves to inventory document
- Availability endpoint (routes/inventory.js): GET /inventory/availability populates inventory, maps to offers, includes `primaryImage: inv.primaryImage, images: inv.images` in offer objects returned to buyer

**Display**:
- Buyer search (Buyer.jsx): renders `{o.primaryImage && <img src={o.primaryImage} alt="Product" style={{ width: "100%", maxWidth: "200px", height: "150px", objectFit: "cover", borderRadius: "8px", marginBottom: "12px" }} />}` in offer cards
- Supplier inventory table (Supplier.jsx): renders 50x50px thumbnail with click-to-open in new tab: `<img src={row.primaryImage} alt="Product" style={{ width: "50px", height: "50px", objectFit: "cover", borderRadius: "4px", cursor: "pointer" }} onClick={() => window.open(row.primaryImage)} />`

**Limits enforced**:
- File count: `Array.from(e.target.files).slice(0, 5)` (frontend)
- File size: `if (file.size > 2 * 1024 * 1024) { setMsg(...); return; }` (frontend)
- File types: accept attribute restricts to jpeg/png/webp (frontend)

Backend validation missing: backend trusts frontend to enforce 5-image and 2MB limits. Base64 strings can exceed 2MB in database storage (2MB binary → ~2.7MB base64). No backend validation of image count, size, or format. Not a blocking issue for pilot (trusted suppliers) but production should validate server-side and consider cloud storage (S3/Cloudinary) instead of base64 in MongoDB.

## Admin inventory view: no image column

AdminStock component (salebysale-admin-frontend/src/pages/Admin.jsx) renders inventory table with columns: Supplier, SKU, Avail, Reserved, Floor, Status, Last Verified, Actions. No image column.

Suppliers upload images, buyers see them in search results, suppliers see thumbnails in their own inventory table, but admins (who need to verify listings, resolve disputes, check product authenticity) cannot view product images in the admin inventory management view.

Fix: add image column to AdminStock table, render thumbnail similar to supplier view:

```jsx
<td>
  {i.primaryImage ? (
    <img 
      src={i.primaryImage} 
      alt="Product" 
      style={{ width: "50px", height: "50px", objectFit: "cover", borderRadius: "4px", cursor: "pointer" }} 
      onClick={() => window.open(i.primaryImage)}
    />
  ) : (
    <span className="muted tiny">No image</span>
  )}
</td>
```

The admin inventory fetch (GET /admin/inventory) likely already returns images/primaryImage fields since the Inventory model has them. Just need to add the column.

## Admin creation script exists

scripts/createAdminSimple.js provides admin creation: edit adminConfig object (name, email, phone, password), run `node scripts/createAdminSimple.js`. Script checks for duplicate email, hashes password, creates User with role "admin", kycStatus "verified", status "active". Default credentials: admin@salebysale.com / Admin@123.

## Privacy enforcement preserved

Buyer views still hide supplier identity: BuyerSearch displays listingLabel ("SELL BY SELL verified stock"), no supplierId fields rendered; BuyerOrder shows "Supplier public identity hidden" message. Admin views explicitly show supplier identity: AdminOrders renders supplierId.shopName, AdminStock displays supplier names, Pending Arrangement tab shows wholesaler and retailer full details. Image upload doesn't leak supplier identity (images stored on inventory, buyer API includes images array but not supplierId object).
